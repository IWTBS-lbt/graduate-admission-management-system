## 1. 需求概述

### 1.1  业务背景

研究生招生信息管理系统的数据管理分为三个阶段：

| 阶段 | 名称 | 主要数据 | 操作 |
|------|------|---------|------|
| 第一阶段 | 考生报名 | 考生档案 | 录入、查询、修改 |
| 第二阶段 | 初试与复试 | 初试成绩、复试成绩 | 成绩录入、分数线筛选、数据分析 |
| 第三阶段 | 录取统计 | 录取名单 | 录取判定、生源分析、计划对比 |

### 1.2  数据实体识别

从业务需求中提取五个核心数据实体：

1. **专业字典（Major）**：专业代码、名称、招生计划数
2. **考生档案（Student）**：考生个人信息与报考信息
3. **初试成绩（FirstScore）**：政治、外语、专业基础三科成绩
4. **复试成绩（SecondScore）**：专业科目、面试、上机三项成绩
5. **录取名单（Admission）**：录取系别、初复试总分、录取状态

## 4. 逻辑结构设计

### 4.1  实体转化为关系模式（第三范式 3NF）

#### （1）专业字典表 relation_major

| 属性 | 类型 | 约束 | 说明 |
|------|------|------|------|
| **major_code** | VARCHAR(32) | PRIMARY KEY | 专业代码（如 CS01、SE02） |
| major_name | VARCHAR(64) | NOT NULL | 专业名称 |
| plan_inside | INT | DEFAULT 0 | 计划内招生人数 |
| plan_outside | INT | DEFAULT 0 | 计划外招生人数 |

> 范式分析：所有非主属性完全函数依赖于主键 `major_code`，满足 3NF。

#### （2）考生档案表 relation_student

| 属性 | 类型 | 约束 | 说明 |
|------|------|------|------|
| **exam_id** | VARCHAR(32) | PRIMARY KEY | 考号（如 2024001） |
| name | VARCHAR(32) | NOT NULL | 姓名 |
| gender | VARCHAR(8) | — | 性别（男/女） |
| age | INT | — | 年龄 |
| political | VARCHAR(32) | — | 政治面貌 |
| is_fresh | TINYINT(1) | — | 是否应届（0-否，1-是） |
| education | VARCHAR(32) | — | 学历（本科/硕士等） |
| source | VARCHAR(64) | — | 考生来源（省份/院校） |
| major_code | VARCHAR(32) | FOREIGN KEY → major(major_code) | 报考专业代码 |
| type | VARCHAR(32) | — | 报考类别（全日制/非全日制） |

> 范式分析：`major_code` 是外键引用的非主属性，其余属性完全函数依赖于 `exam_id`，满足 3NF。

#### （3）初试成绩表 relation_first_score

| 属性 | 类型 | 约束 | 说明 |
|------|------|------|------|
| **exam_id** | VARCHAR(32) | PRIMARY KEY, FK → student(exam_id) | 考号 |
| politics | INT | DEFAULT 0 | 政治成绩（0-100） |
| english | INT | DEFAULT 0 | 外语成绩（0-100） |
| professional_base | INT | DEFAULT 0 | 专业基础成绩（0-150） |
| total | INT | GENERATED ALWAYS AS (politics+english+professional_base) STORED | 初试总分（计算列） |

> 范式分析：所有属性函数依赖于主键 `exam_id`。`total` 由其他三科成绩计算得出，不存在传递依赖（其依赖的是计算表达式而非其他非主属性），满足 3NF。

#### （4）复试成绩表 relation_second_score

| 属性 | 类型 | 约束 | 说明 |
|------|------|------|------|
| **exam_id** | VARCHAR(32) | PRIMARY KEY, FK → student(exam_id) | 考号 |
| professional | INT | DEFAULT 0 | 复试专业科目成绩 |
| interview | INT | DEFAULT 0 | 面试成绩 |
| computer_test | INT | DEFAULT 0 | 上机成绩 |
| total | INT | GENERATED ALWAYS AS (professional+interview+computer_test) STORED | 复试总分（计算列） |

> 范式分析：同 `first_score`，满足 3NF。

#### （5）录取名单表 relation_admission

| 属性 | 类型 | 约束 | 说明 |
|------|------|------|------|
| **exam_id** | VARCHAR(32) | PRIMARY KEY, FK → student(exam_id) | 考号 |
| department | VARCHAR(64) | — | 录取系别 |
| first_total | INT | — | 初试总分（快照） |
| second_total | INT | — | 复试总分（快照） |
| is_admitted | TINYINT(1) | DEFAULT 0 | 是否录取（0-否，1-是） |

> 范式分析：`first_total` 和 `second_total` 是成绩快照，直接归属于该录取记录，不存在传递依赖，满足 3NF。

### 4.2  函数依赖图

```
major:    major_code → {major_name, plan_inside, plan_outside}

student:  exam_id → {name, gender, age, political, is_fresh,
                     education, source, major_code, type}

first_score:  exam_id → {politics, english, professional_base}
             {politics, english, professional_base} → total (计算列)

second_score: exam_id → {professional, interview, computer_test}
              {professional, interview, computer_test} → total (计算列)

admission: exam_id → {department, first_total, second_total, is_admitted}
```

## 5. 物理结构设计

### 5.1  数据库配置

| 参数 | 值 |
|------|-----|
| 数据库名称 | `admission_db` |
| 存储引擎 | InnoDB |
| 字符集 | utf8mb4 |
| 排序规则 | utf8mb4_general_ci（默认） |
| 时区 | Asia/Shanghai |

### 5.2  各表物理存储估算

假设每年考生约 10,000 人，专业约 50 个：

| 表名 | 行估算 | 行长（约） | 表大小（约） | 增长策略 |
|------|--------|-----------|-------------|---------|
| major | 50 | ~200 B | 10 KB | 每年小幅增长 |
| student | 10,000 | ~400 B | 4 MB | 每年线性增长 |
| first_score | 10,000 | ~100 B | 1 MB | 每年线性增长 |
| second_score | 3,000（仅复试） | ~100 B | 300 KB | 每年线性增长 |
| admission | 1,500（仅录取） | ~150 B | 225 KB | 每年线性增长 |

> 总数据量较小（< 10 MB/年），无需分区表或分库分表策略。可保留全部历史数据用于多年趋势分析。

### 5.3  字段类型选择依据

| 字段 | 选用类型 | 选择原因 |
|------|---------|---------|
| exam_id / major_code | VARCHAR(32) | 业务编码，非纯数字，支持字母前缀（如 CS01、2024001） |
| 姓名 / 政治面貌等 | VARCHAR(32~64) | 可变长度，节省空间 |
| 成绩 | INT DEFAULT 0 | 整数分值，默认 0 表示未录入 |
| 总分（计算列） | INT GENERATED ALWAYS AS ... STORED | 自动计算，保证数据一致性 |
| 布尔标记 | TINYINT(1) | MySQL 无原生 BOOLEAN，TINYINT(1) 兼容性最佳 |

## 6. 数据完整性设计

### 6.1  实体完整性

所有表均定义了主键约束（PRIMARY KEY），确保每行数据唯一标识：

```sql
-- 专业表：专业代码作为主键
major_code VARCHAR(32) PRIMARY KEY

-- 学生表：考号作为主键
exam_id VARCHAR(32) PRIMARY KEY

-- 成绩表：考号作为主键（与学生一一对应）
exam_id VARCHAR(32) PRIMARY KEY
```

### 6.2  参照完整性（外键约束）

```sql
-- student.major_code 引用 major.major_code
FOREIGN KEY (major_code) REFERENCES major(major_code)

-- first_score.exam_id 引用 student.exam_id
FOREIGN KEY (exam_id) REFERENCES student(exam_id)

-- second_score.exam_id 引用 student.exam_id
FOREIGN KEY (exam_id) REFERENCES student(exam_id)

-- admission.exam_id 引用 student.exam_id
FOREIGN KEY (exam_id) REFERENCES student(exam_id)
```

**外键约束的设计考量**：

| 决策 | 选择 | 原因 |
|------|------|------|
| 是否使用外键？ | 是 | 数据一致性要求高，单机 MySQL 无性能瓶颈 |
| 删除策略？ | RESTRICT（默认） | 防止误删导致孤立数据 |
| 应用层是否需要额外校验？ | 是 | 在 Service 层做业务语义友好的错误提示 |

**应用层校验示例**（`MajorServiceImpl.removeMajorById`）：

```
删除专业前 → 查询 student 表中是否有关联考生 → 
  有 → 抛出 RuntimeException("该专业下还有考生，无法删除！") →
  无 → 执行删除
```

### 6.3  用户定义完整性（CHECK / 业务约束）

| 约束 | 实现方式 | 说明 |
|------|---------|------|
| 成绩范围 0-150 | 应用层 @Valid 校验 | MySQL 8.0 支持 CHECK 但本设计依赖应用层 |
| 年龄 > 0 | 应用层校验 | — |
| 性别枚举 {"男","女"} | 应用层校验 | — |
| 总分自动计算 | GENERATED ALWAYS AS ... STORED | 数据库层面保证 |

### 6.4  事务管理

在应用层（Spring）使用 `@Transactional` 注解保证关键操作的原子性：

| 操作 | 事务范围 |
|------|---------|
| 删除专业 + 外键检查 | `MajorServiceImpl.removeMajorById()` |
| 复试成绩保存/更新 | `SecondScoreServiceImpl.saveOrUpdateScore()` |
| 录取名单批量生成（先清空 + 批量插入） | `AdmissionServiceImpl.generateAdmissionList()` |

## 7. 索引设计

### 7.1  自动索引

InnoDB 引擎自动为主键创建聚簇索引：

- `major` → 聚簇索引 on `major_code`
- `student` → 聚簇索引 on `exam_id`
- `first_score` → 聚簇索引 on `exam_id`
- `second_score` → 聚簇索引 on `exam_id`
- `admission` → 聚簇索引 on `exam_id`

### 7.2  外键索引

MySQL InnoDB 自动为外键列创建索引（如果尚未存在）：

- `student.major_code` — 用于多表 JOIN 查询

### 7.3  推荐额外索引

当前数据量较小（< 10 万行），外键索引已满足需求。如需扩展到全国范围，建议增加：

| 索引 | 目标表 | 用途 |
|------|--------|------|
| `idx_student_source` | student(source) | 按生源地过滤 |
| `idx_admission_is_admitted` | admission(is_admitted) | 按录取状态过滤 |

## 9. 视图与查询设计

### 9.1  核心关联查询

#### （1）复试资格筛选 — 多条件分数筛选

```sql
-- 同时满足：政治线 AND 外语线 AND 专业基础线 AND 总分线
SELECT s.exam_id, s.name, s.major_code,
       f.politics, f.english, f.professional_base, f.total
FROM student s
INNER JOIN first_score f ON s.exam_id = f.exam_id
WHERE f.politics >= #{politicsLine}
  AND f.english >= #{englishLine}
  AND f.professional_base >= #{professionalBaseLine}
  AND f.total >= #{totalScoreLine}
```

#### （2）各科成绩统计

```sql
-- 以政治为例（英语、专业基础同理）
SELECT
    COUNT(*) AS totalCount,
    AVG(politics) AS avgScore,
    SUM(CASE WHEN politics >= 60 THEN 1 ELSE 0 END) AS passCount,
    SUM(CASE WHEN politics < 60 THEN 1 ELSE 0 END) AS failCount
FROM first_score
```

#### （3）分数段分布

```sql
SELECT
    CASE
        WHEN total >= 0 AND total < 200 THEN '0-200'
        WHEN total >= 200 AND total < 300 THEN '200-300'
        WHEN total >= 300 AND total < 400 THEN '300-400'
        WHEN total >= 400 AND total < 500 THEN '400-500'
        ELSE '500+'
    END AS segment,
    COUNT(*) AS count
FROM first_score
GROUP BY segment
ORDER BY segment
```

#### （4）录取生源分析

```sql
-- 年龄分布（录取考生）
SELECT CONCAT(s.age, '岁') AS `key`, COUNT(*) AS count
FROM student s
INNER JOIN admission a ON s.exam_id = a.exam_id
WHERE a.is_admitted = 1
GROUP BY s.age

-- 来源分布
SELECT s.source AS `key`, COUNT(*) AS count
FROM student s
INNER JOIN admission a ON s.exam_id = a.exam_id
WHERE a.is_admitted = 1
GROUP BY s.source

-- 专业分布
SELECT m.major_name AS `key`, COUNT(*) AS count
FROM student s
INNER JOIN admission a ON s.exam_id = a.exam_id
INNER JOIN major m ON s.major_code = m.major_code
WHERE a.is_admitted = 1
GROUP BY s.major_code, m.major_name
```

### 9.2  计算逻辑说明

| 计算项 | 公式 | 计算位置 |
|--------|------|---------|
| 初试总分 | politics + english + professional_base | 数据库计算列（STORED） |
| 复试总分 | professional + interview + computer_test | 数据库计算列（STORED） |
| 录取总分 | first_total + second_total | 应用层（AdmissionServiceImpl） |
| 各科平均分 | AVG(subject) | 数据库聚合查询 |
| 及格率 | passCount / totalCount | 应用层（StatsServiceImpl） |
| 分数段占比 | segmentCount / totalCount | 应用层（StatsServiceImpl） |

## 10. 建表脚本

完整建表脚本位于 `database/init.sql`：

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS admission_db
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_general_ci;

USE admission_db;

-- 1. 专业字典表
CREATE TABLE IF NOT EXISTS major(
    major_code VARCHAR(32) PRIMARY KEY COMMENT '专业代码',
    major_name VARCHAR(64) NOT NULL COMMENT '专业名称',
    plan_inside INT DEFAULT 0 COMMENT '计划内招生数',
    plan_outside INT DEFAULT 0 COMMENT '计划外招生数'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='专业字典';

-- 2. 考生档案表
CREATE TABLE IF NOT EXISTS student(
    exam_id VARCHAR(32) PRIMARY KEY COMMENT '考号',
    name VARCHAR(32) NOT NULL COMMENT '姓名',
    gender VARCHAR(8) COMMENT '性别',
    age INT COMMENT '年龄',
    political VARCHAR(32) COMMENT '政治面貌',
    is_fresh TINYINT(1) COMMENT '是否应届 0-否 1-是',
    education VARCHAR(32) COMMENT '学历',
    source VARCHAR(64) COMMENT '考生来源',
    major_code VARCHAR(32) COMMENT '报考专业代码',
    type VARCHAR(32) COMMENT '报考类别',
    FOREIGN KEY (major_code) REFERENCES major(major_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考生档案';

-- 3. 初试成绩表
CREATE TABLE IF NOT EXISTS first_score(
    exam_id VARCHAR(32) PRIMARY KEY COMMENT '考号',
    politics INT DEFAULT 0 COMMENT '政治成绩',
    english INT DEFAULT 0 COMMENT '外语成绩',
    professional_base INT DEFAULT 0 COMMENT '专业基础成绩',
    total INT GENERATED ALWAYS AS (politics + english + professional_base) STORED COMMENT '初试总分',
    FOREIGN KEY (exam_id) REFERENCES student(exam_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='初试成绩';

-- 4. 复试成绩表
CREATE TABLE IF NOT EXISTS second_score(
    exam_id VARCHAR(32) PRIMARY KEY COMMENT '考号',
    professional INT DEFAULT 0 COMMENT '复试专业科目成绩',
    interview INT DEFAULT 0 COMMENT '面试成绩',
    computer_test INT DEFAULT 0 COMMENT '上机成绩',
    total INT GENERATED ALWAYS AS (professional + interview + computer_test) STORED COMMENT '复试总分',
    FOREIGN KEY (exam_id) REFERENCES student(exam_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='复试成绩';

-- 5. 录取名单表
CREATE TABLE IF NOT EXISTS admission(
    exam_id VARCHAR(32) PRIMARY KEY COMMENT '考号',
    department VARCHAR(64) COMMENT '录取系别',
    first_total INT COMMENT '初试总分',
    second_total INT COMMENT '复试总分',
    is_admitted TINYINT(1) DEFAULT 0 COMMENT '是否录取 0-未录取 1-已录取',
    FOREIGN KEY (exam_id) REFERENCES student(exam_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='录取名单';
```

## 附录 A：设计关键决策记录

| # | 决策点 | 选择方案 | 理由 |
|---|--------|---------|------|
| 1 | 总分字段实现 | MySQL GENERATED ALWAYS AS ... STORED | 避免应用层计算误差，保证数据强一致性 |
| 2 | 布尔类型 | TINYINT(1) | MySQL 无原生 BOOLEAN，TINYINT(1) 跨版本兼容性最好 |
| 3 | 主键策略 | 业务主键（exam_id, major_code） | 自然主键语义明确，避免多余的自增 ID |
| 4 | 字符集 | utf8mb4 | 支持全 Unicode（含 emoji），MySQL 推荐最佳实践 |
| 5 | 存储引擎 | InnoDB | 支持事务、行级锁、外键约束、崩溃恢复 |
| 6 | 是否分区 | 否 | 数据量小（< 10万行），分区反而增加管理复杂度 |
